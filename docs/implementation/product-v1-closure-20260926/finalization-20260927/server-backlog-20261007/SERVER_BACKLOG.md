**What moves the closure certificate** (`closure_source_digest_v5`): the columns, constraints and triggers (with the md5 of each trigger function) of every table in `public`/`private` (+ `storage.objects`), table owner/ACL/RLS flags, trigger state, and a fixed list of 99 functions (+ the trigger functions of the redaction relations). A NEW table holding personal data also needs an erasure rule (`closure_redaction_relations_v5` / `_scope_v5` / `_patch_v5`, all certified) and a closure-dataset catalog row and an export decision, as D12 did.

## 1. Message read receipts and per-conversation unread state

**Today (DEV, read-only 2026-10-07):** `public.agreement_messages.read_at` exists (since the agreement foundation) but **no function writes it** (0 of 14 messages carry a value; catalog scan: no body updates it). The measured ACK `rpc_mark_displayed_agreement_messages_v1` (B3a) marks only the recipient's `MESSAGE_RECEIVED` **events** (`user_activity_events.read_at`), never the message. `rpc_list_my_conversations_v1` (Poruke inbox, applied 2026-10-03) returns a real unread count for groups and **`unreadMessageCount: null` for every private conversation** ("Legacy Agreement read_at is not maintained by the measured-message ACK"). The client keeps `procitano: null` everywhere ("no authoritative read receipt exists") and its decoders reject a non-null private unread count and any `read_at` key. A "Nova poruka" dot on the Dogovor cards was not found in the client (only state dots and the notification Inbox dot). Groups already have per-recipient read state (`group_message_visibility_v5.read_at`, `rpc_mark_group_messages_read_v5`).

**Privacy facts that decide the design:** `authenticated` has SELECT on `agreement_messages.read_at` and the party policies admit both parties, so **the moment the server writes `read_at`, the sender can read it through PostgREST**, whatever the UI shows: recipient-side unread state and sender-side receipts cannot be separated on that column without an ACL change on a public table (certificate-moving, like PKG-045b). A closure replaces only the closing SENDER's message text; the recipient's `read_at` on the other person's message would survive the recipient's closure unless the certified patch is edited.

**Options:**
- **A (function-only, certificate unchanged):** a v2 of the measured ACK also sets `read_at = coalesce(read_at, statement_timestamp())` on the counterpart's displayed messages; versioned readers (messages page/window v3, `MY_CONVERSATIONS_PAGE_V2`) return `unreadMessageCount` (counterpart messages with `read_at` null) and `readAt` / `procitano` for one's own messages, hidden while the pair is blocked. **This turns read receipts ON for both parties** (owner/legal decision: no opt-out, no notice today). Installed APKs keep calling v1, which must not start writing (otherwise receipts begin silently).
- **B (certificate-moving):** a private read-cursor table (account, agreement, last read message, at) with RLS forced and no client grant, an erasure rule (closure of the reader deletes their cursors) and its re-bind; unread state for the recipient only, receipts for the sender only if and when the owner wants them, through a function that can honour a per-person setting.
- **Not recommended:** unread from `user_activity_events` (recipient-only, and the ACK only settles events whose in-app delivery was not suppressed, so a person with in-app notifications off would show unread forever).

**Recommendation:** ask the owner whether the sender sees "Pročitano" in V1. Yes → A (one function-only package + client v2 readers). No → B (D12-sized package with a named re-bind), or keep the dot client-local until then.

## 2. Saved tasks ("Sačuvaj za kasnije")

**Today:** nothing in the client or on the server (no table, no RPC, no copy; DEV has no saved/favourite/bookmark table). The registry lists saved tasks as out of scope ("tok ne postoji"); the 2026-09-06 spec says "Saved tasks unless owner approves new state". UX note: the FactArt `star` already means "a rating" on the card; a star for saving would collide.

**Minimal design (schema change, CERTIFICATE-MOVING):** `private.saved_needs_v1(account_id → app_accounts, need_id → needs, saved_at, primary key (account_id, need_id))`, index `(account_id, saved_at desc)`, RLS enabled + forced, 0 policies, `revoke all` from public/anon/authenticated/service_role, in no publication; BEFORE INSERT trigger `private.closure_guard_owned_write('ACCOUNT','account_id')`; a SECURITY DEFINER setter (idempotent, `support_auth_v5` + `closure_assert_open`) and a lister that projects the cards through `rpc_discovery_v1` EXACT_PUBLIC (SECURITY INVOKER, so world and closed-account rules apply without re-implementation). A requester's closure patches needs instead of deleting them, so the foreign key survives.

**Certificate steps (the D12 method):** (1) the table moves the schema digest, the program digest's `tables` entry and its trigger function; (2) append it at the END of `closure_redaction_relations_v5` (76 → 77); (3) add it to the `t.account_id=$1` branch of `closure_redaction_scope_v5`; (4) add it to the DELETE list of `closure_redaction_patch_v5`; (5) a `closure_dataset_catalog_v5` row or class (the class text is an owner/legal input); (6) the person's own export gains the saved tasks (projection version and sha change); (7) one guarded statement: pins of the three certified functions, refusals, an isolation probe that returns the digest to `3a785d42…`, the three-place re-bind (`closure_source_v5`, `closure_erasure_source_v5`, the literal in `retention_ai_source_ready`), delta accounting, a revert whose window closes at the first saved row or the first closure; (8) the owner's PRIMENI naming the re-bind. Recommendation: last, and only if the owner wants it in V1.

## 3. Discovery

The reader is `public.rpc_discovery_v1(jsonb)` (DEV md5 `1c602244…`, P6 rollout v3; DISCOVERY-ZAMENE, not applied, pins the same body). Its filter allowlist is exact: all seven keys `text, price, where, places, when, dates, place` are required and no other key is accepted; `price` is only the mode (all / MY_PRICE / OFFERS).

- **3a Real city filter + PLACES by city (function-only, certificate unchanged).** Today `place` matches `p6_discovery_key(area_text) = p6_discovery_key(place)` where `area_text` is "Area, City" (or the area alone when it already names the city, or the city alone): an exact match of the whole normalised label, so "Novi Sad" does not match "Liman, Novi Sad". `approximate_city` is in the column allowlist and returned as `approximateCity`, but it is not a filter key. Needed: an optional `city` key (absent = byte-identical request, `filterKey` and response, the same method DISCOVERY-ZAMENE uses for `forMe`), matched on `p6_discovery_key(approximate_city)`; PLACES grouped by city only when the request asks for it, keeping each row's key = `p6_discovery_key(text)` (the client decoder requires it). Must be built on top of DISCOVERY-ZAMENE (regenerate its pin) or ordered before it with DZ re-pinned.
- **3b "N novih zadataka".** No "last seen" state exists (no column, no table; `opportunity_deliveries.seen_at` has no writer). Function-only: the client keeps its own last-visit time and sends an optional `newSince`; the reader returns `newCount` only when asked (STABLE, no write). A server-kept "last seen" needs a new table (certificate-moving) and a VOLATILE writer.
- **3c Area filter in the first step:** already there ("Ova oblast" sends AREA bounds; the saved work area only positions the camera). No server change.
- **3d Group price:** the reader already returns `requiredSlots`, `coveredSlots`, `requesterPriceRsd` and `priceBasis`; PKG-025b's rule (PER_PERSON multiplies by the covered slots; TOTAL requires covering every slot, no split) is enough for the card. No server change; a server-computed display field would be a function-only addition.

## 4. Diacritic-tolerant search

**Today:** `query_text := lower(p6_discovery_trim(text) collate "sr-Latn-RS-x-icu")`, then `strpos` over the lowered title (and title || area || skills/tools/vehicles): case-insensitive, **diacritic-sensitive** ("cistim" does not find "čistim"). `unaccent` is not referenced anywhere; DEV has `unaccent` and `pg_trgm` available but NOT installed (`postgis` installed); 11 Serbian ICU collations exist. A Serbian fold already exists inside `private.work_kinds_v5` (fold `SR_LATIN_CYRILLIC_V1`, EX-06b, applied, certificate unchanged) but not as a standalone helper.
