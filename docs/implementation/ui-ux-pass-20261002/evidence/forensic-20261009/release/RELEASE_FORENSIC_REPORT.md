## Account closure: executable sequence versus claim

The real entry exists at **Profil → Privatnost i podaci → Zatvaranje naloga**. `ClosureDialog` uses separate owned prepare/review/start/read operations; it journals a stable command before send, binds account incarnation, request/revision/policy hash and reconciles an unknown response rather than guessing success. The final action is unavailable with a stated reason when policy or obligations are not ready.

The admitted AF-D22 path is not merely “disable account”: `rpc_start_account_closure_execution` binds the closure generation; Storage actions are claimed/dispatched once, exact object absence is read back; relational erasure is performed through bounded SQL steps; only after object and relational evidence plus exception checks does the worker invoke Auth admin `DELETE {should_soft_delete:true}`. This retains a pseudonymous Auth subject, removes identity metadata, and database finalization additionally checks deleted_at/password/session state. Source parser rejects CLOSED unless the expected Auth/media/relational outcome, no retained datasets and no exceptions are supplied. `EXCEPTIONS_PENDING` returns EXECUTING, not CLOSED.

UI wording accurately distinguishes “requested”, “ordinary data removed” and “account closed” (`ClosurePresentation.tsx:145`). The new adapter discloses restricted ordinary access, removal of unprotected files/private content, pseudonymous receipts and separately reviewed evidence. Older retained-data adapter remains distinguishable; it must not be marketed as the newer complete-erasure outcome.

**Limits:** root's fresh DEV digest/certificate match and `retention_ready=true` refer to `retention_ai_source_ready()`: they do not prove policy publication, a completed current user deletion, deployed worker flag or real Auth/Storage semantics. The AF-D22 binding source itself returns **`legalPolicyAttested:false`**. It is possible for the code-adapter binding to exist while the legal policy remains unpublished. The five-test-account cleanup preserved Auth credentials/push by owner request and is explicitly not account closure. Local108 certificate/barrier proofs verify install/revert/EXECUTING protections, not full external Auth/Storage destruction. No real deletion was performed by this audit. Minimal closing proof is a disposable, exact-source ordinary account with owned photo/audio/export and messages, legitimate reviewed start, exact worker outcomes, stale-session refusal, user-visible terminal state; separately verify a narrow protected-evidence case and documented resolution. Parent owns whether a safe local probe is possible.

**P0:** no new demonstrated catastrophic defect established by this bounded audit. Absence of a security scan is not a security pass.

**P1 release-critical:** production AAB/environment/push binding; public legal+external deletion resources and actual operator workflow; first-use UGC/AI disclosure/acceptance; additional16KB compatibility risk; final combined business/closure/export QA and independent security gate; inadequate evidence/known poor performance for10k growth.
